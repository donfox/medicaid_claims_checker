Frontend Use Cases

Medicaid Claims Checker · test plan for the running app · status as of October 21, 2026

What this is. The agreed list of things to test in the running Medicaid Claims Checker through its web pages: the Fetch Source page (http://localhost:4000/, Manual Upload and Batch History) and the Rules page (/rules). Each use case names its test files and what the app should show. Engine-only checks are out of scope.
59 use cases
59 with test data
59 checked automatically by ./test.sh

Before you start

  • The engine and Phoenix are running (./start.sh); the dev database has the 17 seeded active rules and the October 2026 NPPES import.
  • Leave Test upload: allow re-submission ticked on the upload page so files can be uploaded again (see the companion guide Repeat Testing with Mock Data). Untick it only for U4–U6.
  • Every path below is relative to mock_data/. Each use case has its own folder, <group>/<ID>_<name>/; the table names the folder and the files in it. The exact expected result of every generated file is in mock_data/manifest.json.
  • Use cases with no folder of their own (N1, R8, U1–U8) use files from other folders.
  • A claim “matches” a rule when the rule fires on it; “Clean” means no rule matches and the NPPES check passes.
  • ./test.sh runs all 59 through the real pages; ./test.sh R5 N7 runs only those.
